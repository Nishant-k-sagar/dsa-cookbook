The Mistral workflow for generating DSA content is **already implemented** in the codebase. This plan outlines how to execute the full pipeline end-to-end to generate content for the DSA Foundations problem sets.

## Pipeline Execution Steps

### Step 1: Generate Seed Files

Creates `seeds/{topic}.json` files with problem selection.

```bash
cd src/web
npm run seed -- --all
```

**Output:** Creates seed files in `seeds/` directory (e.g., `seeds/arrays.json`, `seeds/binary-search.json`)

### Step 2: Generate Content (LeetCode + Mistral)

For each problem:
1. Fetches full problem details from LeetCode (statement, constraints, examples, hints)
2. **Mistral Call 1:** Generates content fields (key_observations, intuition, approach, pseudocode, connection_to_subtopic)
3. **Mistral Call 2:** Generates C++ code implementation

```bash
cd src/web
npm run generate -- --all
```

**Output:** Creates generated files in `generated/` directory (e.g., `generated/arrays.json`)

### Step 3: Build Local Graph Index

Builds `graph.json` for local development mode.

```bash
cd src/web
npm run build:index
```

**Output:** Updates `src/web/public/data/graph.json`

### Step 4: Verify in Local Dev Mode

Start the dev server and verify the content:

```bash
cd src/web
npm run dev
```

The frontend will read from `graph.json` in local mode.

### Step 5: Validate Content (Optional)

Check schema compliance:

```bash
cd src/web
npm run validate
```

### Step 6: Push to Production (Optional)

Push to Azure Cosmos DB for production:

```bash
npx tsx scripts/automation/cosmosPusher.ts --all
```

## What Gets Generated Per Problem

### From LeetCode (Direct Copy)
- `content.statement` - Problem description
- `content.constraints` - Problem constraints
- `content.examples` - Example test cases
- `content.hints` - Hints array
- `title` - Problem title
- `leetcode_id` - LeetCode question ID
- `difficulty` - Easy/Medium/Hard
- `tags` - Topic tags

### From Mistral Call 1 (Content Fields)
- `content.key_observations` - Key insights
- `content.intuition` - Problem intuition
- `content.approach` - Approach explanation
- `content.pseudocode` - Pseudocode solution
- `content.connection_to_subtopic` - How it connects to the topic

### From Mistral Call 2 (Code)
- `code.cpp` - C++ implementation

### Pipeline Logic
- `topic_id` - From topic slug
- `subtopic_id` - From category
- `importance` - Assigned as Crucial/Optional
- `rating` - Calculated based on difficulty + importance
- `pitfalls` - Generated by Mistral
- `time_complexity` - Calculated based on topic + difficulty
- `space_complexity` - Calculated based on topic + difficulty

## Notes

1. **LeetCode API is public** - No authentication required. The client fetches without session cookie. (Note: AGENTS.md incorrectly states LEETCODE_SESSION is required - it's NOT needed for the public API)

2. **Caching** - LeetCode responses are cached for 24 hours in `src/web/.leetcode-cache/`

3. **Error Handling** - If a problem fails, it's skipped and the pipeline continues. Failures are logged at the end.

4. **Mistral Retry** - Up to 5 retries for content, 3 for code, with exponential backoff.

5. **Rate Limiting** - 1 second delay between LeetCode requests.
